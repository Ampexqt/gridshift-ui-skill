# Gridshift UI Reference Guide

This folder is a practical design and implementation playbook for creating original, high-quality technical interfaces. It is not official documentation for any third-party product.

## Recommended reading order

1. `design-principles.md` — overall design philosophy and common anti-patterns.
2. `product-and-information-architecture.md` — dashboard hierarchy and module guidance.
3. `visual-system.md` — colors, typography, borders, surfaces, and textures.
4. `motion-and-interaction.md` — animation and interaction patterns.
5. `responsive-layouts.md` — responsive behavior.
6. `engineering-and-accessibility.md` — implementation and accessibility standards.
7. `reference-sources.md` — how to inspect and verify references responsibly.
8. `quality-checklist.md` — final review before delivery.

## Design intent

Aim for a distinctive, monochrome technical interface when it fits the product: precise, legible, structured, and atmospheric. Terminal motifs and visual effects are optional tools—not a substitute for usability or a clear product purpose.

## Originality and evidence

- Treat examples as inspiration for broad design principles, not templates to reproduce.
- Do not copy another product's distinctive layout, copy, logos, illustrations, or proprietary assets.
- Do not claim that a page, feature, metric, API, or behavior has been verified unless it was actually inspected.
- Label invented demonstration values as mock/demo data.
- Adapt the visual direction to the user's brand, product requirements, existing design system, and audience.
