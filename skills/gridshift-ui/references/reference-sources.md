# Reference Sources and Verification

These links are starting points for product research. They are not a guarantee that every page, feature, or screenshot remains available or unchanged.

## Public starting points

- Use current, accessible public product pages or user-supplied references relevant to the task. Record the URLs actually inspected in project notes when useful.

Open these in a browser before using them as current visual evidence. Access may depend on network availability, authentication, or changes to the product.

## How to inspect references

When browser access or screenshots are available, record:
- Page purpose and primary user action.
- Global navigation and information hierarchy.
- Module order and relative visual weight.
- Typography, spacing, border treatment, and density.
- Node, contribution, and network state vocabulary.
- Interaction behavior and responsive changes.
- Which details are observed versus inferred.

Prefer user-supplied screenshots or an accessible current product page when matching a particular screen. If a page cannot be accessed, state that limitation and do not invent its design.

## Inspiration boundaries

Use reference products to understand broad design patterns and user needs. Create original code, component structure, copy, and visual details. Do not reuse logos, proprietary assets, or distinctive brand elements unless the user has permission and explicitly requests their use.

## Source confidence labels

- **Observed:** directly inspected in the current session.
- **User-provided:** visible in a screenshot, document, or description supplied by the user.
- **Inferred:** a reasonable design proposal, not verified product behavior.
- **Mock:** invented demonstration data, clearly labeled as such.

Keep these categories distinct in both implementation and documentation.
