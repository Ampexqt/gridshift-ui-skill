# Quality Checklist

Use this before marking a UI/UX task complete.

## Product clarity
- [ ] The main user goal is immediately apparent.
- [ ] Node state and primary action are easy to find.
- [ ] Metrics have labels, units, and useful time ranges.
- [ ] Live, derived, unavailable, and mock data are distinguished.
- [ ] No unsupported product mechanics or reward promises were invented.

## Visual quality
- [ ] Monochrome palette is consistent.
- [ ] Primary and secondary information have clear hierarchy.
- [ ] Borders, grids, and textures remain subtle.
- [ ] Typography is aligned and readable.
- [ ] Glow and scanlines do not reduce contrast.
- [ ] Modules are not repetitive decorative cards.
- [ ] Charts and tables are legible and meaningful.

## Motion and interaction
- [ ] Animations communicate real transitions or feedback.
- [ ] Values are not randomized to simulate live activity.
- [ ] All controls have visible interaction states.
- [ ] Important information is available without animation.
- [ ] Reduced-motion preference is respected.
- [ ] Consequential actions provide appropriate confirmation and feedback.

## Responsive and accessible behavior
- [ ] Mobile has a deliberate information order.
- [ ] No unintended horizontal overflow.
- [ ] Keyboard navigation works.
- [ ] Focus indicators are visible.
- [ ] Icon-only controls have accessible names.
- [ ] State is not communicated by color alone.
- [ ] Essential text is readable.

## Engineering
- [ ] Existing architecture and instructions were followed.
- [ ] No unrelated rewrites or unnecessary dependencies.
- [ ] Loading, empty, error, and stale states are handled.
- [ ] Mock data is isolated and labeled.
- [ ] Available lint, typecheck, tests, and build checks were run.
- [ ] Any untested areas or limitations are reported honestly.
